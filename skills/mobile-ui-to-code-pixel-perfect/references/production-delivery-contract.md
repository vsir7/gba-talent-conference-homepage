## 1. 双轴验收

分别报告两个结论，不用视觉通过代替生产通过：

- **视觉还原等级**：`exact / thresholded / masked / blocked`。
- **生产交付等级**：`release-ready / integration-blocked / visual-only / blocked`。

只有视觉门禁达到 `exact`，或用户明确批准的 `thresholded`，并且生产交付达到 `release-ready`，才把页面称为“生产可上线”。

## 2. 交付等级

### release-ready

页面已接入目标项目和正式路由；生产构建、类型、静态检查、相关测试和生产产物预览均通过；真实接口或已批准的稳定数据源已接入；已覆盖本页涉及的加载、空、错误、成功、权限和交互状态；没有未解决的 P0/P1 问题。

该等级表示“前端页面具备上线条件”，不自动表示后端、基础设施、商店审核或整个产品已发布。

### integration-blocked

页面代码和工程质量已达到可接入水平，但正式 API、鉴权、环境变量、路由约定、埋点或发布配置等外部条件缺失。列出责任边界、临时适配层和最小补充材料。不得称为已上线或可直接上线。

### visual-only

页面只完成参考状态，仍含生产路径假数据、占位交互、孤立 HTML、临时资产、开发服务器依赖或未覆盖关键状态。此等级只可作为迭代中间态，不得作为本技能的最终成功交付。

### blocked

无法运行目标项目、构建生产产物、打开页面或执行必要门禁。保存错误输出和阻断证据。

## 3. 生产门禁矩阵

| P01 | 项目原生接入 | 使用现有框架、包管理器、目录、组件体系和设计 token；不另建孤立 demo 壳 |
| P02 | 路由与导航 | 正式路由可直达、刷新可恢复、返回/深链/Tab 行为与项目约定一致 |
| P03 | 数据与类型 | 使用正式 API、类型化适配器或经批准的静态业务数据；生产包不读取 demo fixture |
| P04 | 鉴权与权限 | 登录、无权限、过期、重试和敏感操作遵循项目现有机制；不绕过守卫 |
| P05 | 业务状态 | 覆盖本页涉及的 loading、empty、error、success、disabled、提交中和重复提交防护 |
| P06 | 交互闭环 | 所有可见可操作元素真实可用；无空回调、死链、假 Toast 或仅为截图存在的状态 |
| P07 | 可访问性 | 语义元素、可访问名称、键盘/焦点、对比度、缩放和 reduced-motion 达到项目标准 |

## 4. 静态图与业务信息边界

静态图不能定义 API、权限、埋点、错误恢复、国际化或完整状态。按以下顺序补齐：

1. 读取项目产品文档、接口类型、现有相邻页面和共享组件。
2. 复用已存在的 API client、鉴权、路由、错误边界、Toast、埋点和 i18n 机制。
3. 缺失外部合同时，建立最小类型化适配器并把生产等级标记为 `integration-blocked`。
4. 不凭截图创造业务规则、接口字段、权限或支付行为。

只有用户明确批准的静态内容才可直接进入生产包。开发 fixture、随机数据、当前时间和调试开关必须与生产入口隔离。清单中的生产数据声明使用结构化 `kind=live-api|approved-static|none`：live API 必须登记已哈希的适配器、已哈希的接口合同和目标状态必须实际观察到的成功 fetch/XHR（URL、方法、状态、可选响应哈希）；approved-static 必须绑定文件哈希、批准人、时间和理由；无业务数据时用 `none` 并说明原因。只写“正式 API”几个字不能通过。

## 5. 工程接入规则

- 先识别框架、包管理器、构建工具、路由、状态管理、样式方案、测试体系和浏览器目标。
- 在现有目录和依赖中实现；不要为了单页还原替换项目脚手架、路由或设计系统。
- 优先复用共享布局、按钮、表单、反馈、数据请求和错误处理组件；差异只落在确有设计依据的层。
- 对新增依赖说明必要性、许可证、包体影响和替代方案。普通小图标优先复用项目已安装且许可明确的图标库。
- 不把开发服务器 URL、绝对本机路径、测试账号、密钥或调试参数写入生产代码。

## 6. 构建与测试规则

从项目脚本和 CI 配置中确定真实命令，不默认所有项目都使用 npm：

1. 使用锁文件对应的包管理器；依赖已安装时不重复改锁文件。
2. 运行生产构建、类型检查、lint 和与改动相关的测试。
3. 为关键入口、主要 CTA、数据状态和路由返回补充与风险相称的测试。
4. 若项目已有 CI/release gate，运行其本地等价命令。
5. 从生产产物而非开发服务器做最终 smoke；检查资源路径、代码分割、刷新和直接访问。

所有可计入 `release-ready` 的命令必须通过 `scripts/run_production_command.mjs` 执行并生成独立回执；回执绑定运行 ID、精确命令、项目工作目录、开始/结束时间、退出码、日志及哈希。build 回执还必须绑定当前构建目录和确定性目录哈希。手填 `passed`、只给日志路径或复用旧运行回执均不算证据。

loading、empty、error、success 四态必须各有项目真实测试命令和 `state:<name>` 回执；可访问性、性能、安全、资产许可及每个目标浏览器必须各有 `quality:<name>` 回执。没有业务数据的纯静态页也要用项目测试证明这些状态没有伪入口或破版路径，不能删掉状态数组换取通过。

只修复本次改动导致的问题。发现既有失败时，保存可复现证据并区分“本次引入”和“基线已有”。

## 7. 可访问性、兼容性与性能

- 使用 `button`、`a`、`input` 等语义元素；不要用不可聚焦的 `div` 冒充控件。
- 给图标按钮提供可访问名称；相邻已有可见标签的装饰图标使用空 `alt` 或 `aria-hidden`，避免重复朗读。
- 保证焦点可见、顺序合理、键盘和触摸均可完成主要流程。
- 优先通过透明热区满足触摸尺寸，不因扩大视觉外观破坏像素合同。
- 以项目标准为准验证颜色对比、字号缩放和 reduced-motion。若参考图与无障碍要求冲突，分别报告，不静默改变参考图后仍宣称 exact。
- 以项目 `browserslist`、设备矩阵和性能预算为准；没有标准时先登记临时目标，不制造无证据的“全浏览器兼容”结论。
- 为所有图片声明尺寸；对非首屏图片按项目策略懒加载；压缩生成资产并在最终渲染尺寸下检查清晰度。

## 8. 安全、隐私与资产合规

- 不在前端代码、环境示例、截图或日志中泄露密钥、token、手机号、简历等敏感数据。
- 不直接渲染不可信 HTML；如业务确需富文本，复用项目的清洗与白名单方案。
- 校验外部链接和重定向；新窗口链接使用项目规定的安全属性。
- 记录第三方依赖、字体、普通小图标和图片的包名、版本、来源及许可；禁止远程热链。
- 所有实际加载的图片必须在页面 `assets` 或金刚位资产清单中登记本地文件与哈希；所有网络字体必须在 `typography.fontFiles` 登记字体和许可哈希。普通第三方小图标要在图标角色库存标明包名、版本、导出图标名、实现源码/哈希和唯一 DOM/资产定位器，并与 `utilityIcons.approvedLibraries` 中实际存在且已哈希的 import 文件、name/version 匹配的 `package.json`、许可证逐项对应。可见图标节点用 `data-icon-library/version/name` 与库存建立运行时绑定。
- 最终捕获记录 image/font/script/stylesheet/media 响应，并扫描元素、CSS background/mask/list image/cursor、`content:url(...)`、伪元素中的 data/blob 图片，以及所有 frame 的 document/adopted stylesheet、递归 open Shadow Root、导航前 `attachShadow` 观测到的 closed Shadow Root里的 `CSSFontFaceRule.src`。导航前还用保持原型行为的 Proxy 观测 JavaScript `FontFace` 构造器，覆盖 URL 字符串与 ArrayBuffer/TypedArray 字节源。字符串源必须先交给浏览器 CSSOM 规范化，以消除 scheme 大小写和 CSS 转义差异；每条 `FontFace` API 记录都要分类为 `local(...)`、已捕获的 data/Buffer 资源或有同源响应记录的网络字体，并与唯一资源绑定。静态资源必须与页面同源，图片/字体的响应体哈希必须命中已登记资产；blob 字体/图片、未登记 data/Buffer 字体、未分类/未绑定/孤立的 API 字体资源、观测器被替换或无法审计的 frame/stylesheet 均阻断 `release-ready`。
- 记录图片生成素材的生成方式、最终 prompt、源输出、后处理、哈希和选择结果；不声称生成资产具有未经确认的独占权利。

资产登记最小结构：

```json
{
  "assets": [
    {
      "id": "hero",
      "role": "primary-visual",
      "sourceKind": "original",
      "path": "/absolute/path/src/assets/hero.png",
      "sha256": "sha256:..."
    }
  ],
  "typography": {
    "strategy": "bundled",
    "requiredWeights": [400, 700],
    "fallbackAllowed": false,
    "fontFiles": [
      {
        "family": "Example Sans",
        "weights": [400, 700],
        "path": "/absolute/path/fonts/example.woff2",
        "sha256": "sha256:...",
        "licensePath": "/absolute/path/fonts/LICENSE.txt",
        "licenseSha256": "sha256:..."
      }
    ]
  }
}
```

使用系统字体时改为 `strategy=system`、`fontFiles=[]`、`fallbackAllowed=true`，并由渲染合同锁定 OS 和浏览器。第三方资产另需 `rights.licensePath/licenseSha256`；参考图原子裁片需 `rights.referenceUseConfirmed=true`。

## 9. 生产预览与证据

将证据保存到 `.harness/traces/<task>/<page>/release/`：

- 项目与构建环境摘要。
- build/typecheck/lint/test/e2e 命令、退出码和日志路径。
- 生产预览 URL、启动命令和构建产物路径。
- 路由、刷新、关键交互、状态和浏览器矩阵结果。
- 控制台、页面错误、失败请求、资源 404、字体和溢出检查。
- 性能、可访问性、安全和许可检查的工具输出或人工证据。
- 每个 `responsiveChecks` 必填视口的严格捕获报告，以及每个目标浏览器的通过证据。
- 已知问题、严重度、负责人和是否阻断上线。

最终预览使用 `scripts/start_production_preview.mjs --serve-artifact`，由脚本直接从已哈希构建目录提供文件，并登记 `serveMode=artifact-static`、所服务目录、构建哈希、主文档哈希和进程。`npm run dev`、任意外部命令或只在旁边传入一个无关 dist 目录都不能作为生产因果证据。SSR、边缘渲染、小程序原生包或其他不能由静态构建目录验证的目标，需要为该项目扩展等价的受控发布产物验证器；扩展完成前最高只能是 `integration-blocked`。

清单中的 `evidence.productionCommandResults`、`stateResults` 和 `qualityGateResults` 均只保存回执 JSON 文件路径，不接受内联自报对象。把构建产物路径/哈希、受控 preview 回执、严格捕获、必填响应式捕获、三次稳定性、最终差分与 diff/overlay 哈希、图标角色盘点、适用的素材验证和三份 Markdown 报告全部登记。报告和捕获必须绑定同一运行 ID、当前清单哈希及当前参考图哈希。

在运行视觉门禁前先把 `evidence.visualFidelityResult` 固定为目标输出路径，使视觉结果能够绑定最终清单哈希。先运行 `scripts/verify_visual_fidelity.mjs`；它会重新计算全部稳定性配对和最终像素，不信任已有 metrics 的自报结论。再运行 `scripts/verify_acceptance.mjs` 汇总生产证据；manifest v4 下后者强制读取同一 run、同一清单哈希的已通过视觉结果。任何证据缺失、哈希不匹配或非零退出码都按 fail-closed 处理。

## 10. 严重度与完成声明

- **P0**：数据泄露、越权、白屏、构建不可用、关键流程完全不可用。必须阻断。
- **P1**：主要流程错误、关键状态缺失、严重无障碍/兼容/性能问题。必须阻断。
- **P2**：非关键体验或维护性问题。需记录并由项目规则决定是否阻断。
- **P3**：不影响上线的轻微问题。可带已知限制交付。
