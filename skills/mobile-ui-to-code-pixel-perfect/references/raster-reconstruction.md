## 1. 原图检查

始终使用原始文件并以原始细节打开。先运行 `scripts/inspect_reference.mjs`，再进行视觉分析。

检查：

- 文件是否是真实 PNG/JPG，而不是错误扩展名。
- EXIF 方向、透明通道、ICC 色彩描述和像素密度。
- 是否有浏览器边框、设备壳、批注、缩放痕迹、压缩块或二次截图。
- 图像是视口截图、完整长截图还是局部组件。
- 状态栏和 Home Indicator 是页面内容还是设备壳的一部分。

长图先生成有重叠的垂直切片，逐段查看，不要只分析第一屏。

## 2. 坐标与页面轨道

先测量全局，再测量局部：

1. 画布宽高和页面背景。
2. 状态栏、顶部栏、滚动内容、底部固定区和安全区。
3. 全局左右边距、主列宽、卡片宽度和模块间距。
4. 每个模块的 x/y/width/height。
5. 模块内部图片区、文字区、状态区和操作区的比例。
6. 边框、圆角、阴影扩散范围和叠放关系。

把测量值记录到 `page-analysis.md`。优先寻找重复值并提炼为 CSS token，例如：

```css
:root {
  --page-inline: 16px;
  --section-gap: 20px;
  --card-radius: 16px;
  --control-height: 44px;
}
```

不要一开始把每个像素都写成独立绝对坐标。先建立能解释整页的轨道和组件规则，再对确实需要的局部做 1px 或子像素校准。

## 3. DOM 与素材拆分

把每个可见元素归入一类：

### 代码化元素

- 标题、正文、金额、日期、人数、状态和提示。
- 按钮、Chip、Tab、表单、开关、列表、进度和分割线。
- 卡片容器、网格、弹层、Toast、固定导航和安全区。

这些元素必须使用真实 DOM/CSS/JS。

### 原子素材

- 独立照片、头像、Logo、封面、插画、纹理、普通辅助图标和装饰图。
- 不包含 UI 文字、按钮、标签、卡片布局或多个可交互元素。

优先获取源资产。没有源资产时，只在边界干净、用户有权使用且提取不会包含复合 UI 的情况下，从静态图无损提取原子素材。记录源图、裁切矩形、背景处理和目标容器。金刚位主功能快捷入口也遵循精确源优先；只有用户明确要求重新生成时才进入图片生成分支。

“单一原子素材”不能仅靠主观命名成立：截图裁片不得包含本应由 DOM 渲染的业务文字、可交互语义、多个控件或相邻布局结构。大幅 Hero/Banner 若只有截图裁片且含 UI 文案，按复合区域处理；只有项目提供的独立权威创意资产才可整体登记为原始资产。

使用 `scripts/extract_atomic_asset.mjs` 执行提取；该工具只做方向校正和矩形裁切，不自动缩放、去背景、描边、锐化或颜色调整。任何后处理都会建立新的资产版本和哈希，不能沿用原始提取证明。

### 禁止作为素材的复合区域

- 带标题、金额、状态和按钮的整张卡片。
- 搜索栏、表单、列表行、Tab、底部导航和弹窗。
- 包含多个可分离 UI 元素的 Banner。
- 整页或大段截图背景。

## 4. 字体和文字

不要只依赖 OCR。OCR 适合提取文本候选，但必须逐字核对视觉源。

逐个文本样式登记：

- 字体家族和字体文件。
- 字号、字重、行高、字距和颜色。
- 容器宽度、行数、换行点、截断方式和对齐方式。
- 数字是否使用等宽数字、货币符号是否单独缩放。
- 中文、英文、数字和标点是否发生字体 fallback。

按以下顺序修复文字差异：

1. 字体文件和字重。
2. 文本内容和容器宽度。
3. 字号和行高。
4. 字距和基线。
5. 抗锯齿造成的剩余差异。

不要先用 `top/left/transform` 移动文字来掩盖错误字体指标。

## 5. 颜色、边框与阴影

从原图采样时区分：

- 实色背景与透明叠加。
- 1px 边框与阴影边缘。
- 渐变本身与图片中的光影。
- 圆角裁切造成的混合像素。
- 设计工具色值与经过 ICC/浏览器显示转换后的像素。

先匹配大面积底色，再处理边框、阴影、渐变和透明度。阴影至少登记 x/y、blur、spread、颜色和不透明度。多个阴影不要压成一个近似值。

## 6. 资产重建

先按角色分类，再选择素材。金刚位主功能快捷入口默认使用 `assets/shortcut-asset-set.template.json` 登记有权使用的原始资产或单一原子提取资产；标签保持真实 DOM。只有用户明确要求重新生成，才读取 [generated-shortcut-icons.md](generated-shortcut-icons.md) 并切换到 `image-generation` 策略。

对照片、封面、Logo、背景、插画和非金刚位普通小图标，按以下优先级使用素材：

1. 用户或项目提供的原始资产。
2. 从用户有权使用的静态图中无损提取的原子素材。
3. 能与源图完全匹配的项目图标库或合法第三方库；第三方仅用于非主视觉辅助小图标，并登记包名、版本和许可。
4. 图片生成模型生成的替代素材。

第 4 类通常只能补缺。生成图在主体、纹理、噪声或边缘上通常不会与参考图逐像素一致；无论生成原因是什么，只要整体差分非零，就把 exact 视为 blocked，直到用户批准 thresholded 或批准生成结果成为新的设计基线。

素材接入前锁定：

- 容器尺寸和宽高比。
- `object-fit` 与 `object-position`。
- 主体位置、留白、裁切、圆角和阴影。
- 是否需要透明背景。
- 是否包含本应由 DOM 渲染的文字。

禁止拉伸素材、截图整张卡片、用 emoji 或字符替代图标、用 CSS 几何图临时糊弄复杂视觉。

## 7. CSS 实现策略

先实现参考视口的确定性布局：

- 页面壳使用明确的宽度、最小/最大宽度和背景。
- 只保留一个主滚动容器，除非参考设计明确存在嵌套滚动。
- 给固定顶部/底部区域预留内容空间和安全区。
- 使用 grid/flex 建立稳定轨道；设置 `min-width: 0` 防止文字撑破。
- 对自适应卡片使用内容驱动高度；只在参考确实固定高度时锁定。
- 对重复组件提炼共享 token 和组件类，不逐页复制近似参数。
- 明确图片尺寸，避免加载后布局跳动。

允许对本来固定或叠放的元素使用绝对定位。不要用整页绝对定位逃避文档流，也不要用全局缩放把不正确布局压进参考尺寸。

参考视口通过后，再添加响应式规则。每次响应式修改后重新运行参考视口门禁，防止回归。

## 8. 差异定位顺序

每轮查看 `diff.png`、`overlay.png`、差异包围盒和指标，按以下顺序处理：

1. **画布错误**：宽高、背景、整体缩放、DPR 或截图模式错误。
2. **全局偏移**：状态栏、顶部栏、主内容或底部固定区整体错位。
3. **模块几何**：卡片尺寸、轨道、间距、圆角和图片比例。
4. **排版**：字体、字号、行高、换行和基线。
5. **视觉参数**：颜色、边框、阴影、透明度和渐变。
6. **资产像素**：图标、照片、插画、纹理和裁切。
7. **栅格化尾差**：抗锯齿、色彩配置、浏览器/OS 字体渲染。

每轮只改变一组相关变量。记录修改、指标变化和剩余差异，不反复凭感觉改多个区域。

## 9. 长图和多状态

长图还原时：

- 使用重叠切片逐段分析。
- 先确认是完整页面截图还是多个视口拼接；拼接缝不能被当成真实布局间距。
- 捕获前预滚动以触发懒加载，再回到顶部执行 full-page 截图。
- 记录最终文档高度；高度不一致时不要裁图强行比较。

多状态还原时：

- 每个状态使用独立参考图、状态脚本、截图和指标。
- 不用默认态通过结果替代弹层、选中态、输入态或成功态验收。
- 未提供参考图的状态只做功能和设计系统一致性检查。
